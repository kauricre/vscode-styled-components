# Bump `vscode-css-languageservice` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump `vscode-css-languageservice` to the latest 6.x so the shared hoisted copy the extension and TS plugin use gains 2026 CSS knowledge, clearing the 161 validation + autocomplete audit findings; verify with a re-audit.

**Architecture:** One dependency-range change in `package.json`. npm hoists a single newer copy satisfying both the extension (`^6.x`) and the plugin (`^6.2.4`); the plugin's runtime diagnostics and the extension's esbuild-bundled data provider both pick it up. Verification re-runs the audit's Node probes (A + B) and regenerates the report.

**Tech Stack:** npm, `vscode-css-languageservice` (6.x), the existing `audit/` harness (`node:test`, `node audit/run.js`, `node audit/report.js`).

## Global Constraints

- **Only bump `vscode-css-languageservice`** (caret on latest 6.x, NOT 7.x). No other production dependency version changes. No `src/` runtime changes, no `syntaxes/*.json`, no `colorProvider.ts`.
- **Keep the `css-latest` dev alias** — it is Probe A's bundled-vs-latest reference.
- **After install, there must be no nested `vscode-css-languageservice`** under `node_modules/@styled/typescript-styled-plugin/` — the plugin must keep using the single hoisted copy.
- **Probe C (Extension Host) is intentionally NOT re-run** — a css-languageservice bump cannot affect highlighting (grammar) or color (`colorProvider.ts`). Verify with Probe A + B only (`node audit/run.js`), then regenerate the report (`node audit/report.js`), which reuses the existing `editor-findings.json`.
- **`dist/` is git-ignored** — `npm run compile` is a verification step (proves the bundle still builds), not a committed artifact.
- **`npm run audit:test` must stay green.** The bump invalidates the existing "overlay is unknown" test; Task 1 updates it (see Step 1).
- **Commits:** use `git commit --no-gpg-sign` (passphrase-locked SSH signing). The pre-commit hook runs `prettier --check .`; `docs/superpowers/audit` is prettier-ignored, but keep any edited `.js`/`.md` outside that dir prettier-clean.
- **Branch:** `feat/bump-css-languageservice` (already checked out).

- [ ] **Step 1: Update the version-coupled test (write the failing guard first)**

The current test asserts `overlay` IS flagged on the stale engine — the bump will make that false. Read `audit/probe-corpus.test.js`, then replace this test:

```js
test("the reported overlay property produces an 'Unknown property' diagnostic on the stale engine", () => {
  const diags = validateCss(mod, ".x { overlay: auto; }", "scss");
  assert.ok(
    diags.some((d) => /unknown property/i.test(d.message)),
    JSON.stringify(diags)
  );
});
```

with these two tests (keep the existing "known-good CSS produces no diagnostics" test above them unchanged):

```js
test("a genuinely unknown property still produces an 'Unknown property' diagnostic (detection mechanism works, version-independent)", () => {
  const diags = validateCss(
    mod,
    ".x { xyzzy-not-a-real-property: 1; }",
    "scss"
  );
  assert.ok(
    diags.some((d) => /unknown property/i.test(d.message)),
    JSON.stringify(diags)
  );
});

test("the previously-unknown 'overlay' property is recognized after the css-languageservice bump (no unknown-property diagnostic)", () => {
  const diags = validateCss(mod, ".x { overlay: auto; }", "scss");
  assert.ok(
    !diags.some((d) => /unknown property/i.test(d.message)),
    JSON.stringify(diags)
  );
});
```
